1. GENERAL INFORMATION
--------------------------------------------------------------------------------

Framework:        Laravel 12 (PHP 8.2)
Auth packages:    tymon/jwt-auth (JWT), spatie/laravel-permission, DomPDF
Base URL (dev):   http://localhost:8000/api
Base URL (prod):  https://your-domain.com/api
Version prefix:   /api/v1
Full local base:  http://localhost:8000/api/v1

Authentication:   Authorization: Bearer <jwt-token>
               OR: X-API-Key: <long-lived-api-key>
               OR: Authorization: Bearer <long-lived-api-key>
                  All routes below are protected by middleware
                  "api.auth" + "ensure.active" EXCEPT the "Public" group.
                  api.auth accepts either a JWT or a long-lived API key, so
                  existing frontend tokens keep working unchanged.

Request headers:  Content-Type: application/json
                  Accept: application/json
                  Authorization: Bearer <token>
                  X-API-Key: <api-key>          (external integrations)
                  X-Webhook-Signature: sha256=... (signed webhooks)
                  X-Webhook-Timestamp: <unix-ts>
                  X-Webhook-Id: <unique-event-id>
                  X-Webhook-Event: <event-name>
                  X-Requested-With: XMLHttpRequest

Response format:  { "success": true, "message": "...", "data": { ... } }
                  List responses include a "meta" object:
                  { "current_page": 1, "last_page": 5, "per_page": 15, "total": 75 }

Status codes:     200 OK | 201 Created | 204 No Content
                  400 Bad Request | 401 Unauthorized | 403 Forbidden
                  404 Not Found | 422 Validation Error | 429 Rate Limit | 500 Error

Notation:         "PUT|PATCH" means both verbs are accepted.
                  "GET|POST /path" means both verbs are registered.
                  Paths shown are full paths including /api/v1.

5. CROSS-CUTTING BEHAVIOUR & DOCUMENTED CONVENTIONS
--------------------------------------------------------------------------------

Sorting:         ?sort_by=last_name&sort_order=asc
Filtering:       resource-specific, e.g. ?status=scheduled&date=2024-01-15&doctor_id=1
Searching:       /patients/search?term=john&field=first_name

Documented rate limits (NOT actually enforced - no middleware attached):
  Login             5 attempts/minute
  Register          3 attempts/minute
  Password Reset    3 attempts/hour
  General API       60 requests/minute
  Report Generation 10 requests/minute

Multi-tenancy:   Most controllers filter by auth()->user()->institution_id
                 ad hoc; dedicated institution middleware exists but is unused.
CORS:            config/cors.php allows GET/POST/PUT/PATCH/DELETE/OPTIONS on api/*

6. KNOWN GAPS / DRIFT (verify before integrating)
--------------------------------------------------------------------------------

* No role/permission, rate-limit, institution, or audit middleware is attached
  to any route, even though those middleware classes exist.
* ~21 registered apiResource routes have no controller handler (marked
  "HANDLER MISSING" above) and will throw "Method does not exist".
* GET /api/v1/cash-register/movements actually creates data (verb mismatch).
* docs/API.md claims rate limits that are not implemented.
* README.md mentions GET /api/v1/dashboard/stats - not registered.
* Frontend calls /dashboard/charts, /dashboard/activity, /invoices/stats and
  PUT /consultations/{id} - none have backend routes.
* No Swagger/OpenAPI spec or Postman collection in the repository.
